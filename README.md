# swmm5-fsharp

EPA SWMM 5.2.4 in F#, written by a translator that reads EPA's C, and judged against EPA itself: the binary
`.out` file byte for byte, and the `.rpt` report line for line except the three lines that print the wall clock.

**Result: 480 of 480 models identical** (`fsharp/results/fs_1.json`, log `fsharp/results/fs_1_run.txt`). The
independent rerun from a clean build of the committed sources, `fs_v`, gave 480 of 480 again
(`fsharp/results/fs_v.json`). The 480 took 372 seconds of wall time run one at a time (the sum of the per-model
times the gate records, .NET start-up included; the slowest, EPA/72_H&H_Elements(2).inp, took 29 s). No
interleaved benchmark against EPA was run, so no speed ratio is claimed.

It is not a new engine and not a wrapper: there is no C in it and it calls no other port's code. Every number it
writes is EPA 5.2.4's, including the results of EPA's own defects wherever EPA's behaviour is defined
(`lessons/02-epa-defects-found.md`). Its math functions are glibc's own, called in the system libm by P/Invoke.

## The parity contract

The same as the earlier ports' (see `go/` or the swmm5-go repository): EPA SWMM 5.2.4 built from the USEPA v5.2.4
tag with gcc 13.3 `-O2` on x86-64 Linux with glibc 2.39 (`ref/Makefile`), on a processor with FMA and AVX2; each
model run in its own folder; pass = `.out` byte-identical (when EPA writes one) and `.rpt` identical after removing
`Analysis begun on`, `Analysis ended on` and `Total elapsed time`, the exit code the same (EPA's command line always
exits 0). When an input error stops EPA before it writes results, the engine must not write a results file either.
Corpus: the 480 gate models of `gate/models_all.tsv` from SWMMBobSWMM6/1729-SWMM5-Models-2030.

## Build and run

Requires the .NET 8 SDK (tested with **SDK 8.0.132**, runtime Microsoft.NETCore.App 8.0.32) and its F# compiler
(**F# 8.0, fsc 12.8.102.0**, `sdk/8.0.132/FSharp/fsc.dll`). `fsharp/build.sh` calls that compiler directly against
the shared framework, with **FSharp.Core 8.0.102** unpacked from the SDK's offline package
(`FSharp/library-packs/FSharp.Core.8.0.102.nupkg`), so no NuGet access is needed. It takes about 30 seconds.

```sh
fsharp/build.sh                                   # -> fsharp/bin/runswmm.dll (+ FSharp.Core.dll)
fsharp/runswmm model.inp model.rpt model.out      # = dotnet fsharp/bin/runswmm.dll ...
```

To regenerate the engine: `python3 tools/c2x/emit_fsharp.py fsharp/gen` from the repository root (needs
`pip install libclang==18.1.1` and the clang 18 headers at `/usr/lib/llvm-18/lib/clang/18/include`; about 30 s).

## How it was made: C without return, break, continue or goto

`tools/c2x/emit_fsharp.py` builds on the C# back end's analysis (`emit_cs.py`: the front end's pointer modes, names,
function-pointer types) and its type model, which suits .NET: `int`, `uint32`, `int64`, `uint64`, `float`,
`float32`; `char*` as `CPtr` (a byte array and an offset, `p.[i]` a signed char); structs as classes with
`val mutable` fields and `Clone()` for C's value copy; a pointer that is indexed as an array; a scalar pointer
parameter as a `byref<T>` (passed as `&x`, `&a.[i]`, `&o.f`); function pointers as delegates. Functions are static
members of one type `S` (so they can call each other in any order); C globals and static locals are module-level
mutable values; records are one recursive group of classes.

F# has no `return`, `break`, `continue` or `goto`, and an `if` or a loop is an expression. Each C function body is
therefore first built as a small tree (blocks, ifs, loops, switches and jumps) and restructured before any F# is
written:

1. **Unreachable code is dropped**: what follows a statement that cannot complete normally (a jump, an `if` whose
   branches both jump, `for (;;)` with no break, a switch with a default whose every section jumps).
2. **The common early exit becomes an `else`**: in `if (c) <jump>; rest`, where one branch always jumps and the
   other can complete, the rest of the block moves into the branch that completes:
   `if c then <jump> else rest`. A chain of such tests becomes `if ... elif ... else`.
3. **Every other jump sets a flag** (`__ret` for a return, `__brkN` or `__cntN` for the loop it leaves, `__swN` for
   a switch it leaves), and the statements the jump would skip are wrapped in `if not (flags) then`. A jump needs no
   flag when nothing would run between it and its target: a return or a `continue` in tail position, the last
   `break` of a switch section. A return only stores its value in `__rv`, which the method returns at its end.
4. **Loops test their flags before C's condition**, `while not (__brkN || __ret) && cond do`, so the condition is
   not evaluated after a break, as in C. A `for` loop's increment runs after the body when no break or return has
   happened (so it does run after a `continue`); `do ... while` sets `__goN` from the condition at the end of the
   body; the break flag is cleared each time the loop is entered, the continue flag each iteration.
5. **switch becomes `match`** on the integer constants (default last, as `_`); a section that can complete
   normally would fall through, so the following section's statements are appended to it (none of EPA 5.2.4's
   switches needs this once exhaustive inner switches are recognised; the emitter reports any it writes).

No exception is used for control flow. After unreachable code is dropped, EPA 5.2.4's 951 translated functions hold
2,336 returns, 476 breaks from switch sections, 86 continues and 50 breaks from loops; 1,785 of the returns, all
476 switch breaks and 85 of the continues became structure, and 551 returns, the 50 loop breaks and 1 continue set
a flag (`python3 tools/c2x/emit_fsharp.py` prints these counts; `fsharp/results/emit_stats.txt`).

The other F#-specific rules, each written out by the translator:

- **No implicit numeric conversion.** Every conversion clang records is explicit (`float x`, `int64 x`,
  `float32 x`, `R.D2I x` for double to int with x86-64's rule, NaN and out of range giving INT_MIN), literals carry
  their type (`1u`, `1L`, `1UL`, `1.0f`), shifts take an `int` count. A compound assignment computes in C's common
  type and converts back (`int x; x += 1.5` becomes `x <- R.D2I(float x + 1.5)`).
- **Assignments are statements.** An assignment, `++`, `--` or `op=` used as a value becomes
  `(let __t = v in x <- __t; __t)`; where the location would be evaluated twice and computing it has side effects,
  its parts are bound to temporaries first. `sscanf` targets are passed as boxes (`IBox`, `DBox`, ...) and copied
  back after the call; `&x` passed where the callee indexes an array becomes a one-element array, copied back.
- **Locals are declared once**, mutable, at the top of the function (C may jump past a declaration in a switch,
  and an F# `let` is scoped to the rest of its block); parameters the body assigns or whose address it takes are
  copied into mutable locals of the same name.
- **Names.** F# keywords and the names of F# functions the generated code uses (`float`, `int`, `ignore`, `max`,
  ...) get a trailing `_`. A parameter whose name begins with a capital letter gets a `p_` prefix: F# reads an
  upper-case name in a parameter list as a pattern, and a `byref` parameter so named cannot be assigned (`*Qw = ...`
  in `inlet.c` failed to compile with FS0027 until this rule existed).
- **Pointers and null.** Pointer equality is `obj.ReferenceEquals` (or `R.peq` for `char*`, which compares the
  buffer and the offset); a null pointer whose F# type depends on how a declaration is used is written
  `Unchecked.defaultof<_>` and typed by F# from where it goes.

When the port disagreed with EPA, the fix went into the translator or the runtime, never into the generated file.

## The runtime and the math library

- **Math.** `Libm` declares `exp`, `log`, `log10`, `pow`, `sin`, `cos`, `tan`, `asin`, `acos`, `atan`, `floor` and
  `ceil` with `DllImport("libm.so.6")` (and `SuppressGCTransition`, which makes the call cheap): the engine calls
  glibc's own routines, so it inherits glibc's choice of FMA routines on processors that have them, as EPA does.
  `Math.Sqrt` and `Math.Abs` are used for `sqrt` and `fabs` (exact operations: `sqrtsd` and a sign-bit mask, as
  gcc compiles them). The P/Invoke lookups bind to libm's default symbol versions, which are the versions EPA
  imports (`exp@GLIBC_2.29`, `log@GLIBC_2.29`, `pow@GLIBC_2.29`, `sin@GLIBC_2.2.5`, ...; lessons/19):
  `fsharp/test/check_binding.sh`, output `fsharp/results/libm_binding.txt`. Checked bit for bit against C, NaN
  signs included, by `fsharp/test/run_checks.sh` (`fsharp/results/checks.txt`): 10,000,416 random arguments over
  SWMM's ranges (`tools/libm/test/mkvectors.c`), 3,300,000 edge cases (`mkedge.c`) and 4,000,112 arguments for
  sqrt, floor, ceil and fabs (`fsharp/test/mkexact.c`, the Ruby port's): **0 differ**.
- **printf/strtod/sscanf** (`Crt.fs`): digits of `%f`, `%e` and `%g` from exact big-integer arithmetic, rounded half
  to even as glibc does; strtod reads decimal (through .NET's correctly rounded `Double.Parse`), hexadecimal
  (rounded exactly), `inf`, `infinity`, `nan` and `nan(payload)` as glibc does; `atoi` and `sscanf %d` saturate as
  `strtol` does before the value is cut to 32 bits. Checked against glibc 2.39 by the same script (the 1,394,252
  cases of `tools/crt/test/mkfmt.c`): **1 differs**, `%#g` of 999999.5 (glibc `1.e+06`, the port `1.00000e+06`),
  the case every runtime reports; SWMM never uses `%#g`.
- **Integers.** F#'s `/` and `%` on `int` truncate toward zero as C's do, and its `+`, `-`, `*` wrap; double to
  `int`, `long` and `unsigned` go through `R.D2I`, `R.D2L` and `uint32 (R.D2L x)`, which give x86-64's results for
  NaN and out-of-range values (INT_MIN, LONG_MIN), not .NET's. `fsharp/test/intcheck.c` (gcc -O2) and
  `fsharp/test/intcheck.fsx` print the same 25 lines of divisions, remainders, conversions of NaN, infinities and
  out-of-range doubles, and narrowing casts (`fsharp/results/intcheck.txt`).
- **stdio**: .NET `FileStream`s behind a 64 KiB `BufferedStream`, with C's end-of-file flag, `fgets` semantics and
  positioning; the 8-byte `off_t` positions output.c writes with `sizeof(INT4)` are written as their low 4 bytes.

## How it was checked

| Run | Engine | Models | Result |
|---|---|---|---|
| (scratch) | lone copies of the decks in a scratch folder, `fsharp/test/scratch_gate.py` | all 480 | 470 identical to the reference, 10 identical to EPA on the same copies |
| **fs_1** | **final build** (`fsharp/build.sh`) | **all 480** | **480 of 480** |
| fs_v | `Engine.fs` regenerated by `tools/c2x/emit_fsharp.py` and built by `build.sh` in a clean folder extracted from the commit with `git archive` | all 480 | 480 of 480 (382 s) |
| fs_main | built by `build.sh` in a clean clone of the working repository at commit e63bef0 (the main session's check) | 45 drawn at random from the 480, plus the three decks that SAVE and USE `cho.txt` | 48 of 48 |

The F# engine passed every gate model on its first gate run; the four translator fixes it needed (null pointers
typed from their declaration, pointer-typed record fields, upper-case parameter names, exhaustive switches) were all
found by the compiler or by reading the output before any model ran.

All runs: `fsharp/gate/run_chunk.sh NAME IDS`, which runs `python3 gate/gate.py NAME
"$PWD/fsharp/runswmm_saves.sh" --ids IDS -j 1 --timeout 1800 --prune` inside `flock` on the shared corpus lock, with the output folder
in `/dev/shm` (lessons/22). `runswmm_saves.sh` is the Ruby port's wrapper with the engine changed (SAVE files and the
backslash-named `[LID_USAGE]` report files backed up and restored; lessons/29). `Hydrology/cho.txt` was 1,114,474
bytes, md5 5b0ca1fe78588202fa779dbfa417b089, after the last run.

Before the gate, `fsharp/test/scratch_gate.py` ran the engine on a lone copy of each of the 480 decks in a scratch
folder (never inside the corpus) and compared it with EPA's reference outputs, or, for a deck that needs other
files, with EPA run on the same lone copy: 470 identical to the reference outputs and the other 10 (decks that read
rain, climate or RDII files from their folder) identical to EPA on the same copies, 0 different
(`fsharp/results/scratch_gate_1.txt`; that build differs from the final one only in the names of the delegate
lambdas' parameters).

For the independent rerun, `Engine.fs` regenerated in the clean folder was byte-identical to the committed one, and
the clean build's `runswmm.dll` has the same module id and the same IL in all 3,795 method bodies as the build fs_1
ran (`fsharp/test/ilcmp.fsx`), and the two `.pdb` files are identical. The two `.dll` files differ in 81 bytes: the
compiler pads the (path-mapped) PDB name in the debug directory to the length of the real build folder's path, so
the clean build, made in a longer folder, carries 108 more zero bytes there, and the debug data after it moves.

The main session then checked the result itself: it built the port in a clean clone (the `.pdb` identical to the
one fs_1 ran, the `.dll` different in the same 81 bytes of debug-directory padding) and ran fs_main, ids in
`fsharp/gate/ids_main_check.txt`, record in `fsharp/results/fs_main.json`. `cho.txt` was unchanged after it.

## What this does not show

- That SWMM is right: identical to EPA means EPA's answers, good or bad.
- Other platforms: the port calls the system libm, so on another machine it should follow EPA built there; only
  x86-64 Linux with glibc 2.39 was run.
- Paths no gate model exercises: streets and inlets (one deck, which stops on input errors), climate files,
  USE HOTSTART, USE INFLOWS, USE RUNOFF, and C switch fall-through with code in the section (none in EPA 5.2.4, so
  that part of the translator has never run); the stepping API is translated but only the command line was gated.
- .NET checks every array index, so an out-of-bounds access would stop the engine with an exception rather than
  read past the end as C may; the gate run is in that sense a checked run. Integer arithmetic is unchecked, as in C.
- Speed beyond the gate's own clock: no interleaved benchmark against EPA was run (lessons/07).
- No person has reviewed the generated code line by line; the evidence is the gate and the runtime and math
  checks.
